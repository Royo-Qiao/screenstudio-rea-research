# 用 REA 研究 Screen Studio：怎样验证 macOS 原生录制与真实视频导出

这是待发布的 X 文章草稿；尚未发送。

研究 Electron 桌面应用时，我遇到了一个容易误判的问题：应用显示导出完成，文件却没有真正生成。一次工具预检、一次静态分析，甚至一个成功日志，都不足以证明完整录屏流程已经跑通。

这次对象是 Apple Silicon 上的 Screen Studio 3.7.3-4540。我把观察拆成四层：REA 对 Electron fuses 和 Mach-O 的静态检查；应用实际原生录制到保存项目；用户亲手操作鼠标并编辑验收；最后对导出视频做完整解码。每层分别保留结论和限制。

两个具体的排查点很实用。第一，展开 ASAR 后仅有正确文件字节还不够：辅助程序的可执行权限丢失，会破坏后续导出。第二，原生录制辅助程序的 Foundation 原子写入并不完全遵守 TMPDIR，需要核对它实际使用的临时目录。它们都是这次环境的观察，不能当成适用于所有 Electron 应用的通则。

已有原生录制样本为 H.264、1104×720、60fps、3337 帧，完整解码通过。真人项目统计得到 938 个鼠标位置、15 次点击、10 次按键和一段缩放。公开工具只输出统计，不输出用户按了哪些键。

边界也一样重要：联网授权验证失败；应用离线重启通过不等于整机重启通过；这也不是从零重写的 Screen Studio。我公开的是原创检查工具和研究记录，不是应用安装包或激活方案。

仓库包含三个只读 Python 工具：应用声明与 Mach-O 检查、原生项目事件统计、ffprobe + ffmpeg 视频导出核验。希望它们能帮助你验证自己的 Electron/macOS 录屏研究，而不是停在“看起来成功”。

仓库：https://github.com/Royo-Qiao/screenstudio-rea-research
